### §2.6 THE PER-OP ROLLBACK COMPOSITION — the reach, the order, the guard and the floor

1. **THE REACH, AS THIS UNIT COMPOSES IT** (`P: §B.3`): **when an attempt reaches `FAILING`, the kernel
   composes the store's own `rollback` verb OVER EACH OP THE ATTEMPT CREATED — `rollback(op.opId)` PER OP —
   and it performs NO commit-level rollback, because the store declares none.** **THE COMPOSITION'S
   CANDIDATE SET IS THEREFORE EXACTLY `AttemptRecord.ops` — THE OPS THIS ATTEMPT CREATED AND NO OTHERS: a
   store operation the attempt did not create is NEVER a member of the set the kernel composes over, and
   the set is read from the attempt's own `ops` member and from nothing else** (`CC-12`; `CC-13`).
   **AND THE CALL LIST IS ONE SET WITH ONE HOME WHILE THE COMMIT REGISTRY IS ITS OTHER TERM, DECLARED HERE SO THE TWO ARE NEVER TWO DIFFERENT SETS; AND THE TWO READINGS `A105` `Q2` SUPERSEDES ARE WITHDRAWN BY NAME — *"a single registry keyed by the attempt's address holding one attempt-scoped set"* and *"a held set held for anything wider than one call's processing"* (`CY-1`; `CY-2`)** (`VC-7`; **RE-DERIVED AT THE `A105` LANDING PASS, WHICH LANDS THE ARCHITECT'S `Q2`/`Q3`**): **`AttemptRecord.ops` is the attempt's whole creation record, and the set the kernel CALLS OVER is its FILTERED FORM — `ops` minus every op standing AT OR BEFORE the `checkpoint` op, minus the op the `checkpoint` member NAMES, AND NOTHING ELSE: the list is FIXED WHEN THE COMPOSITION BEGINS and holds each still-owed op EXACTLY ONCE, so the composition ISSUES ONE CALL PER STILL-OWED OP — the one reading item 5 (a) fixes, the steps already recorded serving only to PREVENT A SECOND CALL OVER THE SAME `opId` and never to drop a member from the list.** **AND *"AT OR BEFORE"* IS DECIDED OVER THE REGISTRY'S OWN ORDERED OP SEQUENCE AND OVER NOTHING ELSE** (`CY-4`; `A105` `Q2`): **THE COMMIT REGISTRY IS KEYED PER PROCESSING — A PROCESSING BEING THE EXTERNAL-SURFACE WRITE OR DELETE CALL: EVERY SUCH CALL HAS A KEY AND AN ENTRY, HOLDING THAT CALL'S OWN OPS AND THE OPS ITS REPAIR FUNCTIONS MADE, A WRITE MADE DURING ANOTHER'S PROCESSING TAKES ITS OWN ENTRY, AND A READ OPENS NO PROCESSING, TAKES NO KEY AND ADDS NO ENTRY (a read making no change and therefore needing no constraint check), WHILE A WRITE/DELETE CALL THAT OPENS NO ATTEMPT STILL HAS ITS OWN ENTRY UNDER ITS OWN DECLARED KEY** — **the keying rule's ONE home being `contract.md §5.7`, a nested processing's ops standing in its OWN entry and never its encloser's** — **so the attempt's own entry carries its own ops IN THE ORDER ITS PROCESSING MADE THEM, and AN OP IS AT OR BEFORE THE `checkpoint` OP IFF `ops` HOLDS THAT OP AND THE ATTEMPT'S OWN REGISTRY ENTRY STANDS ITS POSITION AT OR BEFORE THE ENTRY THAT HOLDS THE `checkpoint` OP — that entry being THE ENTRY THAT HOLDS THE `checkpoint` OP WHERE THAT OP IS ANOTHER PROCESSING'S — THE ENTRY ITSELF BEING THE PROCESSING'S CARRIER, NO `processingId` MEMBER STANDING ON ANY RECORD AND THE POSITION OF A FOREIGN `checkpoint` OP BEING READ BY FINDING THE ENTRY THAT HOLDS THAT OP (`A: docs/decisions.md` · `A107` `D4` — the RULING, THIS BEING ITS ONE HOME, `A106` `Q4`'s DERIVATION BEING CONFIRMED BY IT AND DISPLACED AS A DERIVATION; `DB-3`; `VG-8`) — WHICH IS DECIDABLE FOR AN OP STANDING IN NO EARLIER STEP'S `undoneOps` MEMBER, THAT OP BEING HELD BY THE REGISTRY FOR EXACTLY THE REASON THAT THE `checkpoint` OP IS.** **SO THE TWO SITE READINGS ARE ONE: the call list is read FROM `AttemptRecord.ops` as its candidate membership and FROM THE ATTEMPT'S OWN REGISTRY ENTRY as its still-owed membership, and the difference between them is DECLARED and not resolved by a drive — it is exactly the ops the checkpoint bounds and the ops already undone.** **AND AN OP THE ATTEMPT OWED THAT IS NOT A MEMBER OF THE CALL LIST IS PASSED TO THE STORE VERB BY NO CALL OF THIS COMPOSITION: the composition reaches NO ADDRESS AND NO OP OUTSIDE ITS OWN CALL LIST, so a still-owed op that lies at an address outside EVERY performed call's own subtree — an op whose named op no performed call lies above — STANDS AT THE END STATE, and WHERE SUCH AN OP STANDS THE END STATE IS NOT THE LAST VALID STATE AND THIS UNIT SAYS SO RATHER THAN IMPLYING OTHERWISE** (`CX-13`; `A: docs/specs/storeroom-native/write-and-read.md §6.4` item 1's `M-5`; item 5 (a); `contract.md §5.7`, `P-TP-7`). **AND AN OP THE ATTEMPT OWED THAT IS NOT A MEMBER OF THE CALL LIST IS PASSED TO THE STORE VERB BY NO CALL OF THIS COMPOSITION: the composition reaches NO ADDRESS AND NO OP OUTSIDE ITS OWN CALL LIST, so a still-owed op that lies at an address outside EVERY performed call's own subtree — an op whose named op no performed call lies above — STANDS AT THE END STATE, and WHERE SUCH AN OP STANDS THE END STATE IS NOT THE LAST VALID STATE AND THIS UNIT SAYS SO RATHER THAN IMPLYING OTHERWISE** (`CX-13`; `A: docs/specs/storeroom-native/write-and-read.md §6.4` item 1's `M-5`; item 5 (a); `contract.md §5.7`, `P-TP-7`).
2. **THE ORDER OF THE COMPOSITION, DECLARED BY THE KERNEL AND BY NOTHING STORE-SIDE:** **the repaired ops
   first, in REVERSE of the order they were created, and the attempt's first write's op LAST.** **This order
   is the kernel's own bookkeeping and is NOT a store clause** (`contract.md §5.5`).
   **AND EVERY OP THE ATTEMPT CREATED HOLDS A DECLARED POSITION IN IT, WITH NO OP UNPLACED** (`CC-12`):
   **the repaired ops are ALL the ops in `ops` other than the attempt's first write's op** — `ops` admits
   nothing else, because the write's op is the attempt's first entry and every other entry was produced by a
   repair (`kernel-surface.md §2.3` item 2's add rule) — **so the composition is `ops` minus its first entry, reversed, then
   that first entry last, and the order is TOTAL over `ops`.** **AND THIS ORDER GOVERNS BOTH ARMS: WHERE THE ATTEMPT PASSED NO CHECKPOINT, THE CALL LIST IS ITEM 2'S OWN — THE WHOLE LIST — AND THE WHOLE LIST IS WHAT ITEM 8 (iii) READS, IN THIS ORDER; the sentence that once stood here, reading that arm as *"THE ATTEMPT'S OWN FIRST OP ALONE"* with every op of `ops` losing its declared position, IS WITHDRAWN BY NAME AT THAT SAME HOME WITH `A111`, WHILE EVERY OP THE ATTEMPT CREATED STILL HOLDS ITS DECLARED POSITION IN THE TOTAL ORDER ABOVE ON BOTH ARMS** (`VE-10`; `VE-11`; item 8 (iii)). **A drive that finds an op of `ops` in
   neither part has found an op that entered `ops` through no declared act** (`parameter-semantics.md
   §2.7`; `e2e-scenarios.md`'s `E2E-C-2`).
3. **THE PER-OP CALL'S OWN RECORD — DECLARED HERE BECAUSE THE COMPOSITION'S OBSERVATION NEEDS A MEMBER AND
   NO FORM CARRIED THE STORE'S ANSWER** (`CC-14`): **each per-op `rollback` call returns the store's own
   `RollbackResult`, and the kernel records ONE `RollbackStep` PER CALL, in the order the calls were
   performed:**
   ```
   RollbackStep {
     opId:        string,      // the opId the kernel PASSED to that call, echoed
     undoneOps:   string[],    // the store's own `undoneOps` member, VERBATIM where the call returned; [] where it threw
     restoredTo:  BaseState,   // the store's own `restoredTo` member VERBATIM where the call returned; the state the op's
                               // own subtree stood at, read by the store's own `read(address, tier?)` verb, where the call threw

     failed:      boolean,     // true iff that call THREW, false iff it returned
     checkpoint:  string | null // THE OP — the opId of the op whose LANDING left the attempt's LAST VALID STATE, or null where no such
                               // landing exists FOR THAT ADDRESS. THE MEMBER'S DOMAIN IS DECLARED ONCE AT ITS HOME, item 8 (iii) below —
                               // this block carries the member and its TYPE and CITES that home: the domain and the null arm are
                               // STATED THERE AND NOT HERE. It is the composition's TARGET AND ITS STOP OP, ONE VALUE WITH ONE READING,
                               // COPIED by this shape from the attempt's own `attempt-lifecycle.md §2.4` item 1 `checkpoint` member —
                               // THIS SHAPE IS NOT THE MEMBER'S HOME — and the op it may name is read at item 8 (iii) too
                               // (`A: docs/decisions.md` · `A104`),
   }
   ```
   **`[T: the rollback step's member set | DECLARED-DEFAULT]`** — **alternatives priced: (i) carrying the
   store's whole `RollbackResult` object — REFUSED, because the kernel's record would then hold a store

   side of the surface; (ii) recording nothing and letting a drive re-read the journal — REFUSED, because
   the journal is not readable, enumerable, addressable or deletable by any call but `rollback` itself

   composition performed at all; **(iii) THE FOUR-MEMBER FORM WITH NO STATUS MEMBER — REFUSED, because a
   call that THREW returns no `RollbackResult` at all and the two members that would otherwise be read

   one that threw except by parsing `answer`** (`RC-10`).** **Reversal point: a fresh ruling plus a bounded amendment. AND THE `answer` MEMBER'S VALUE DOMAIN IS CLOSED AND BOUNDED, DECLARED SO *"ANY OTHER CODE THE CALL RAISES"* IS READ AGAINST A FINITE SET** (`CX-14`): **`answer` is EXACTLY ONE OF TWO THINGS — the literal `'ok'` WHERE THE CALL RETURNED, or ONE MEMBER OF THE STORE'S OWN CLOSED `15`-MEMBER CODE SET (**⟶ RE-SPELLED 2026-10-15 BY THE `CODES`-CLASS SWEEP (`role_spec_writer`): the `15` here is this clause's FILING-TIME figure, standing BYTE-FOR-BYTE above and read THROUGH this reading; the store's LIVE SET CARRIES `16` MEMBERS, ALGEBRA `11 + 2 + 1 + 1 + 1 = 16` ✓, the fifth term being `ConstraintListInvalid` at rank `16`**) WHERE THE CALL THREW — and NO THIRD FORM EXISTS: a code outside that set is not a member of this member's domain at all, so a step whose `answer` carries such a token has read a code the store's own contract forbids the store to throw** (`fail-surface.md §3` items 1–2 — the closed `15`, `11 + 2 + 1 + 1 = 15` ✓, no member minted, renamed or re-triggered by this unit; `contract.md §5.7`).
   **AND THE ONE ARM THE STATUS MEMBER EXISTS FOR, PRINTED AS A CLAUSE OF ITS OWN BECAUSE A THROW IS NOT A
   RETURN** (`RC-10`): **where a per-op call THROWS the store's own code — the floor's `RollbackCompacted`,

   step records: `failed: true`, `answer` = the STORE'S OWN CODE it threw, `undoneOps: []` (NOTHING WAS

   STOOD AT, read through the STORE'S OWN `read(address, tier?)` VERB — the store's declared read of `docs/specs/storeroom-native/write-and-read.md §3`, whose returned state is the answer `RollbackResult.restoredTo` mirrors on the returning arm — which is the state the all-or-nothing failure left it

   **THE STEPS APPEAR IN `AttemptReport.rollback` AND IN THE CLOSED RECORD'S `rollback` MEMBER, IN
