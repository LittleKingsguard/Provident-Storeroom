### §2.4 THE ATTEMPT — its record, its states, its transition table and its trigger selection

1. **THE ATTEMPT'S RECORD SHAPES.** **The attempt's record is THE KERNEL'S OWN** (`P: §B.4`) **and its
   members are the three the proposal names, one for one:** **the returned messages (`log`), the ops created
   (`ops`), and what has already been run (`ran` and `appliedRepairs`) — plus the identity, the commit, the
   open flag, the composition's performed calls and the checkpoint pin.** **AND THE NINE MEMBERS ARE THE OPEN ATTEMPT'S SHAPE AND ONLY IT: the CLOSED attempt's record is the five-member `AttemptReport` of `kernel-surface.md §2.1` item 3, so `open`, `ran`, `appliedRepairs`, `commit` and `ref` are read off an OPEN attempt and never off a closed one** (`NV-2`; item 7 (ii)).
   ```
   AttemptRef  { id: string }                 // the attempt's identity: a non-empty, kernel-unique token
   AttemptRecord {
     ref:              AttemptRef,            // the attempt's identity
     commit:           CommitRecord,          // the commit that opened the attempt, VERBATIM
     ops:              JournalOp[],           // EVERY op the attempt created, in CREATION order
     log:              LogEntry[],            // the message log, seq ascending
     ran:              string[],              // the (address, id) pairs WHOSE FUNCTION HAS RUN, as pair keys — one entry per pair, added at that pair's FIRST evaluation
     appliedRepairs:   string[],              // the (address, id) pairs WHOSE REPAIR HAS RUN and produced an op
     open:             boolean,               // true while the attempt is open, false once closed
     rollback:         RollbackStep[]         // the per-op rollback calls PERFORMED; [] until a failure arm
     checkpoint:       string | null          // the `opId` of the op whose landing left the attempt's address in the attempt's last valid state; null where no op left one
   }
   ```
   **`[T: the attempt record's member set | DECLARED-DEFAULT]`** — **alternatives priced: (i) a single
   opaque record with no member named — REFUSED, because a TestWriter derives no state from an opaque record
   and the filing's union row `U5` asks for the SHAPES; (ii) the store's own journal op reused as the
   attempt's carrier — REFUSED, because that would place kernel state on the store's closed record, which
   `docs/specs/storeroom-native/write-and-read.md §6.2` closes and `P: §B.4` forbids.** **Reversal point: a
   fresh ruling plus a bounded amendment.**
   - **AND WHAT `AttemptRef.id` IS, AND WHAT ITS ABSENCE MEANS, NAMED BECAUSE `K-4`/`K-5` TAKE IT AS THEIR
     ARGUMENT** (`VF-3`; `CC-19`): **`AttemptRef.id` is a non-empty string, minted by the kernel at `K-2`,
     unique within the kernel instance, and it is the TOKEN `K-4`/`K-5` accept as their `attempt` argument —
     `K-3` RETURNS it on the report, `CommitRecord.attempt` carries it at `K-2`, and `K-4`/`K-5` accept
     either the `AttemptRef` record or its `id` string and NOTHING ELSE.** **An argument that is neither,
     or an `id` the kernel holds no attempt for, is `KC-2`** (`kernel-surface.md §2.1` items 4–5; `parameter-semantics.md
     §2.15`; `fail-surface.md §2`'s `KC-2`).
2. **THE PAIR KEY, STATED BECAUSE TWO OF THE MEMBERS USE IT, AND ITS SPELLING FIXED HERE** (`VF-3`): **a
   constraint's identity in the attempt's bookkeeping is the PAIR (`address`, `id`), spelled as ONE key
   token: **THE ADDRESS HALF IS THE ADDRESS'S OWN SEGMENTS, EACH SPELLED AS ITS OWN CLASS MARKER (`i` FOR AN INDEX, `k` FOR A KEY), THEN ITS OWN LENGTH IN DECIMAL DIGITS — BEING THE SEGMENT'S OWN SIGNLESS DIGITS WHERE THE CLASS IS AN INDEX AND ITS CHARACTER COUNT WHERE THE CLASS IS A KEY — THEN A `:`, THEN THE SEGMENT VERBATIM, THEN `;`, AND THE SEGMENTS SO SPELLED JOINED WITH `/` — AND THE ID IS APPENDED AFTER A `#`** — so the pair (`['a','b']`, `'x'`) spells `k:1;a/k:1;b#x`, the pair (`['a']`, `'b#x'`) spells `k:1;a#b#x`, the pair (`['a/b']`, `'c'`) spells `k:3;a/b#c` and the pair (`['a','b']`, `'c'`) spells `k:1;a/k:1;b#c`, the pair (`['v',3]`, `'x'`) spells `k:1;v/i:3;#x` — ITS SECOND SEGMENT AN INDEX, SO MARKED AND SPELLED BY ITS OWN DIGITS AND NOT BY A CHARACTER COUNT — and the empty address spells the empty string, so the pair (`[]`, `'x'`) spells `#x`.** **THE SPELLING IS INJECTIVE OVER THE WHOLE DECLARED SEGMENT DOMAIN, AND THAT CLAIM IS RE-DERIVED HERE BECAUSE IT ONCE OVER-BROADENED: EVERY SEGMENT IS SPELLED WITH ITS OWN CLASS MARKER — `i` FOR AN INDEX, BEARING THE SEGMENT'S OWN SIGNLESS DECIMAL DIGITS IMMEDIATELY; `k` FOR A KEY, BEARING THE SEGMENT'S OWN LENGTH IN DECIMAL DIGITS IMMEDIATELY — AND EACH IS THEN FOLLOWED BY A `:`, BY THE SEGMENT VERBATIM AND BY `;`.** **THE INJECTIVITY, IN ONE LINE OF REASONING: the class marker tells the reader WHICH of the store's two segment classes the token carries, the digits after it tell the reader EXACTLY how many characters its own segment has and end where its own `:` begins, and the `;` is a delimiter the field's own grammar cannot carry, so a segment ends where its own field says and a `;`, a `:`, a `/` or a `#` INSIDE a segment is that segment's own character and never a separator** — **SO NO TWO DISTINCT SEGMENT LISTS SPELL ONE STRING — AND NO SEGMENT'S OWN CLASS IS LEFT TO BE INFERRED FROM ITS DIGITS, WHICH IS EXACTLY WHAT THE WITHDRAWN UNMARKED SPELLING DID: IT SPELLED AN INDEX `3` AND A KEY `'3'` IDENTICALLY** — `String(3)` and `'3'` BOTH SPELLING `3` — so its *"injective"* claim was FALSE OVER THE DECLARED DOMAIN, which is closed at exactly two classes and whose integral class is an UNBOUNDED-DIGIT class (`A: docs/specs/storeroom-native/store-model.md §1.5` items 1–2), even though no drive of this directory reached the collision, a parent being a `VEC` xor a `MAP` (`A: docs/specs/storeroom-native/store-model.md §1.4`). THE TOKEN HAS NO SECOND SPELLING AND NO READER MAY STRIP THE CLASS MARKER: a key or a token spelled by the withdrawn rule is re-spelled by this one, and no census of this directory moves (`ran` and `appliedRepairs` holding these tokens exactly as before, and the `KC` set `8` on `13` sites unmoved — the `KC-1` row's refused-shape enumeration being re-derived from the store's own segment domain and NOT from this spelling, so it is UNCHANGED by this item and is not re-derived anywhere for it).** — and the length is decimal digits and the separator is `/`, NEITHER OF WHICH A SEGMENT'S LENGTH DIGITS CAN BE, so the boundary between any two segments is recoverable and no two distinct segment lists spell one string. **THE TWO CASES THE OLD SPELLING COLLIDED ARE THEREFORE DISTINCT UNDER THIS ONE: the pair (`['a/b']`, `'c'`) and the pair (`['a','b']`, `'c'`) are spelled `3:a/b#c` and `1:a/1:b#c`, so they are DIFFERENT KEYS; and the same holds of EVERY pair whose first member carries a `/`, a `#`, the empty segment `''` (spelled `0:`) or a NUL/control character (carried VERBATIM inside that segment's own length-bound field, its length counting it), because a segment is NEVER READ AS A DELIMITER — the ONE HOME OF THIS SPELLING IS HERE, and a drive that builds a key string builds it by this rule and by no other** (`VF-3`; `RC-5`). **AND THE REGISTRY'S OWN READER READS THIS FORM AND NEVER A BARE `#`-SPLIT: the id follows the ONE `#` the address half cannot carry — a length is decimal digits and a `:` follows them, so NO `#` STANDS IN THE ADDRESS HALF** — the id being the SECOND member and the address's segments the FIRST. **AND THE OLD SPELLING IS WITHDRAWN BY NAME FOR THE SECOND HALF IT ONCE CARRIED: *"the two are DIFFERENT keys because the address half is joined before the separator is written"* is WITHDRAWN — a join performed before the separator is written does NOT make two distinct pairs distinct, because ONE segment may carry the separator — WHILE THE FIRST HALF, the address's own segments joined and then the id appended, STANDS as the form above re-spells it** (`S6`). **AND WHAT `ran` and
   (`['a','b']`, `'x'`) spells `k:1;a/k:1;b#x` and the pair (`['a']`, `'b#x'`) spells `k:1;a#b#x`, **and the two are

3. **THE ATTEMPT'S STATES, EACH NAMED SO A `P-SM` ROW CAN DRIVE IT.**
   - **`OPEN`** — the attempt stands in the registry and has an `AttemptRecord`. **The kernel's own act of
     `K-2` moves an address from unheld to `OPEN`.**
   - **`EVALUATING`** — the constraint pass runs: **constraint functions run, the log appends
     `constraint-check` entries, and a violation moves the attempt by the FOUR COMBINATIONS item 4's disjointness rule settles and by no other predicate: `REPAIRING` where the violated pair is NOT IN `ran` before the evaluation AND a repair IS registered for it (arm `(b)`); `FAILING` with `KC-3` where it is NOT IN `ran` before the evaluation and NO repair is registered for it (arm `(c)`); and `FAILING` with `KC-5` or `KC-6` where it IS IN `ran` before the evaluation, by `appliedRepairs` membership (arms `(e)`/`(f)`) — so a pair IN `ran` violated again is NEVER arm `(c)`, whatever its registration.
     THE FOUR COMBINATIONS ITEM 4 PRINTS SETTLE IT — AND NOTHING ELSE DECIDES.**
   - **`REPAIRING`** — the repair function runs through the caller's own verb, **the op it produced is
     ADDED to `ops`, and the attempt returns to `EVALUATING` for THAT op — AND *"THE OP IT PRODUCED"* IS READ HERE AS THE `op` MEMBER OF THE REPAIR'S OWN RETURN AND NOTHING ELSE: the repair's `{ok: true, op}` return carries THE OP ITS OWN EDIT LANDED — the store's own `write` return's value — the kernel reads it off that return, and the op it APPENDS to the attempt's `ops` IS `returnValue.op`, so this state's own transition has exactly ONE carrier** (`A: docs/decisions.md` · `A110`; the shape's ONE HOME being `parameter-semantics.md §2.7`, cited here and re-derived nowhere — **including the no-second-route clause, which that row's `observable` cell carries and this item does not restate**).** **A repair that does not produce
     an op moves the attempt to `FAILING` — AND THIS IS THE ARM `(d)` THAT CARRIES THE WHOLE OF *"DOES NOT PRODUCE AN OP"*, DECLARED SO EVERY RETURN SHAPE LANDS IN IT BY NAME: `{ok: false, message}` · a return read as that arm by `parameter-semantics.md §2.8`'s outside-form rule · and an `ok === true` return whose `op` IS ABSENT, `undefined`, OR NOT THE OP THE REPAIR ACTUALLY LANDED — the app's own defect, disposed of as a FAILED REPAIR and never as a kernel defect of its own, with the kernel's generated sentence naming the unrecognized or unlanded `op`, the `repair-run` entry appended, and the terminal token `KC-4` exactly as a `{ok: false, message}` return's is.**
   - **`FAILING`** — the attempt's failure arms: the log's final entry is appended, the per-op rollback
     composition runs over `ops` — its walk reading the commit registry before any terminal act of this arm
     —, **the registry entry is REMOVED STRICTLY AFTER THAT COMPOSITION HAS RUN AND ITS LAST CALL RETURNED
     OR THREW, so no removal precedes or interrupts the walk that reads the entry it removes (`CY-5`), and the kernel's own form is THROWN
     carrying the log.**
   - **`PASSED`** — every constraint passed: **a `commit` log entry is appended, the registry entry is
     REMOVED, and the `AttemptReport` is RETURNED.**
   - **`CLOSED`** — the attempt's record after disposal, **reachable from `FAILING` and from `PASSED` and
     from nowhere else.** **An attempt's record is NEVER disposed of by any other transition, and no attempt
     is left in the registry by either terminal arm.**
    **AND WHICH TERMINAL ARMS REMOVE THE ATTEMPT'S OWN COMMIT-REGISTRY ENTRY IS FIXED HERE, SO NO ARM'S OWN CLAUSE IS READ AGAINST `D5`'s CLEARING RULE** (`CX-5`): **the `PASSED` arm removes it, as printed above; and each `FAILING` arm removes it WHEN, AND ONLY WHEN, THAT ARM'S COMPOSITION IS A SUCCESSFUL ROLLBACK — the predicate whose ONE home is item 8 (i) (3) defines — cited here and re-spelled nowhere (`VG-5`) — and its per-op calls therefore leave NO STILL-OWED OP UN-UNDONE.** **SO AN ATTEMPT THAT FAILS WHERE SOME STILL-OWED OP WAS NEVER UNDONE — a call that THREW, and every op after it the composition never reached — LEAVES ITS OWN ENTRY STANDING, its owed ops held by the attempt that owns them; and NO EDIT OP IS EVER ORPHANED, because an op an attempt created is held by THAT attempt's entry and by no other ATTEMPT's** (`contract.md §5.7`; item 8 (i) (3); `composition-and-states.md §2.6` item 5 (a)). **THE TWO CLAUSES NEVER DISAGREE: the clearing rule fixes WHAT A SUCCESSFUL ROLLBACK DOES — it clears the registry — and this clause fixes WHICH ATTEMPT IS STILL HOLDING OPS WHEN IT DID NOT** (`Q-C`; `A: docs/decisions.md` · `A103`).

## §3. `A112` DELIVERY-MODEL RE-SPELL, 2026-10-13

**THE RULING THIS SECTION RECORDS IS `A: docs/decisions.md` · `A112` — the architect's own words of 2026-10-13: *"The Rust store returns the handles, and then the JS surface functions run first the constraints and then, after all constraints pass, any other listeners before returning to the calling process. On a write, all constraints need to be run again anyway so all triggered constraints need to be run, sifting pending out of the set is not needed. Write the entire returned set of triggered constraints as pending and check off as they pass. Likewise, all listeners are not run until the constraints pass, so all listeners are pending on every write."* — AND THIS SECTION NAMES THE SITES THIS PART RE-SPELLED FOR IT. It restates no standing clause.**

1. **THE STATUS HEAD, THE `A108`/`A109` LANDING-PASS BLOCKS.** **WHAT MOVED: the `pending` member's reading and the loop's rank.** **IT STOOD:** *"a caller-made write's not-yet-invoked handles stand in `CommitRecord.pending`"* and *"the caller's own loop over `CommitRecord.pending` IS LAYER (b)'s ONLY INVOKER."* **IT STANDS NOW:** the member carries **the ENTIRE RETURNED SET OF TRIGGERED CONSTRAINTS, each entry leaving it ONLY BY BEING CHECKED OFF AS IT PASSES — sifting a subset out of the returned set being UNNECESSARY AND UNLAWFUL** — and the caller's own loop is **ONE INVOKER AMONG THE JS SURFACE'S OWN ORDERED LAYERS AND NOT THE ONLY ONE**, the store returning the handles and invoking nothing. **NO FIGURE OF THE HEAD MOVES** — the open `AttemptRecord` `9`, the closed `AttemptReport` `5`, `RollbackStep` `6`, the `8`-arm table and the four-arm disjointness rule all stand as printed, and the named-shape census does not move (no `K-6`, no callback parameter, no new named shape).
