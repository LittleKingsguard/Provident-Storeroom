## §2. `LIVE/INSTALL`, defined — instrument, site, label

### §2.1 The definition, in one line

**THE INSTALL OF THE RELEASED BYTES, BY A PACKAGE MANAGER, IN A CLEAN DIRECTORY, EXERCISED THROUGH THE CLAIMED ESM ENTRY TO A FINAL RESOLVED STATE — ADDITIVE, `APP` STILL `NONE`, AND NEVER A SUBSTITUTE FOR THIS UNIT'S OWN NODE LEGS.** `[A1 docs/specs/storeroom-publish-proposal-review.md §5.1 item 5 — the gate-1 record's own determination, and `archive/gate1/storeroom-publish-review/3-architecture.md §A.4`'s table carried whole | requirement]`

### §2.2 The instrument

1. **A REAL PACKAGE MANAGER, OPERATING ON A PACKED OR RELEASED TARBALL** — **not a local directory copy, not a symlink and not a workspace link** — **at the version the tag names.**
2. **A CLEAN DIRECTORY WITH NO REPOSITORY IN ITS ANCESTRY AND NO `build/Release` BESIDE THE ENTRY.** **Both halves matter: the ancestry half means no parent manifest can satisfy the entry's own resolution, and the `build/Release` half means rung two cannot fire — so what the battery observes IS rung one, which no in-place battery can reach.**
3. **ONE REAL NODE PROCESS**, running the entry's own import and a minimal exercise to a final resolved state. `[A1 docs/specs/storeroom-publish/contract.md §4.2 | declared parameter semantics]`

### §2.3 The site

**THE SITE IS NAMED PER FIGURE, AND IT HAS THREE PARTS, EACH PRINTED WITH THE FIGURE THE BATTERY REPORTS:** **(i)** **the clean directory's path class** — the directory's own path, or its class where a path would disclose the machine; **(ii)** **the pack/install command as it was issued**; and **(iii)** **the repository root the bytes were produced at.** **A figure reported without its site is VOID.** `[A1 docs/specs/storeroom-publish/contract.md §6 — the figure table, whose every row carries its site | numeric or census claim]`

### §2.4 The label

1. **THE LABEL IS `LIVE/INSTALL`**, **this unit's own, declared here and at the contract document's `§4.1`.**
2. **IT IS NOT AN `APP`-GREEN, AND `APP` REMAINS `NONE`.**
3. **IT IS CITED — NEVER INSERTED — AT THE SIBLING DIRECTORY'S OWN LAYER CLAUSE**, **because that directory's layer vocabulary is not one of the two homes the amendment reaches** (`[A3 docs/specs/storeroom-js/acceptance.md §4.2 — the sibling LAYER label and its `APP` `NONE` reading, cited and never re-labelled | cross-reference]`).
4. **AND THE LABEL'S OWN ARITHMETIC, PRINTED WITH ITS TERMS: `1` label, `1` layer, `1` instrument — `1 + 1 + 1 = 3` declared parts, and the label adds NO layer to any other unit's vocabulary.** `[A1 docs/specs/storeroom-publish/contract.md §4.2 | numeric or census claim]`

## §3. What it verifies, and what it must NOT claim

### §3.1 What it verifies — five observables

| # | The observable | Why it is this layer's and not another's |
| --- | --- | --- |
| **1** | **THE RELEASED BYTES INSTALL AT ALL** | a tarball's own content — its allowlist, its manifest and its pins — is a property only a real install exercises |
| **2** | **THE CLAIMED ESM ENTRY RESOLVES AFTER INSTALL** | the entry is reached by the package's own NAME, so the resolution is the registry's and the consumer's resolver's, not the repository's |
| **3** | **RUNG ONE — THE PLATFORM PACKAGE — IS THE RUNG THAT FIRES IN A PUBLISHED INSTALL** | **no in-place battery can reach this observable, because rung two's module-relative path exists in the checkout and rung one's package does not** |
| **4** | **THE VERSION READ DOES NOT REFUSE THE RELEASED ARTEFACT** | the addon's own self-report and the package's own `version` are two artefacts of the RELEASE, and their agreement is a fact of the published bytes rather than of the tree |
| **5** | **THE DECLARED FAILURE ARM IS WHAT AN UNCOVERED TARGET MEETS** | the arm's own subject and form are exercised only where no platform artefact can be resolved |

`[A1 docs/specs/storeroom-publish/contract.md §4.3 | requirement]`

### §3.2 What it must NOT claim — five prohibitions, each with its reason

| # | The prohibition | Its reason |
| --- | --- | --- |
| **1** | **NOT AN `APP` FIGURE** | **the assembled/`APP` layer for every unit of this project is `NONE`; this unit delivers a library and artefacts, and exposes no rendered surface, no IPC and no UI tool surface** |
| **2** | **NOT A RE-MEASUREMENT OF THE SIBLING UNIT'S OWN FIGURES** — **its `113` JS cells, its `240` blind assertions and its `91` live assertions** | **those are ANOTHER unit's figures at ITS sites and layers, and this battery drives one install of released bytes and one Node process; a re-measurement would be a figure about a different artifact** |
| **3** | **NOT A VALIDATION OF ANY CONSUMING APPLICATION** | **`HO-1`…`HO-7` remain handoffs, this unit wires no consumer, and no consumer's configuration is written by any pass** |
| **4** | **NOT A PROOF THAT NO CONSUMER HAS EVER LOADED THE PACKAGE** | **no instrument in this topology can falsify that universal negative, so it stays a `STATEMENT` and never becomes a figure** (`docs/specs/storeroom-publish/contract.md §0.3` · `PUB-DD-14`) |
| **5** | **NOT A RE-LABELLING OF THE STORE'S OWN FIGURE** | **the store's `379` is the store unit's, at its own site and layer, and it is not this unit's at any spelling; the store's green is never re-run as this unit's acceptance leg** |

## §4. The post-release constraint — the ceiling, stated

1. **`LIVE/INSTALL` PRESUMES REGISTRY STATE — five published names and a published main package.**
2. **SO IT CANNOT RUN BEFORE THE RELEASE ACT, AND ITS FIGURE CANNOT EXIST AT THIS UNIT'S GATES 1–4.**
3. **ITS PHASE IS MARKED BLOCKED IN THE PLAN (`Q10`, BLOCKED BY `Q9`), AND IT IS ADDITIVE AND POST-RELEASE BY CONSTRUCTION.**
4. **RUNNING IT EARLY — OR REPORTING ITS FIGURE BEFORE THE RELEASE — IS A STOP CONDITION OF THIS UNIT AND NOT A RISK** (`docs/specs/storeroom-publish/implementation-plan.md §5` · stop condition `I`) — **this item stands, and the item above states the same ceiling at the contract document's own home.**
5. **AND ONE CONSEQUENCE THE PLAN PRINTS AND THIS PART RE-STATES, SO THE `DONE` CRITERION IS NOT READ AS UNREACHABLE: a `DONE` row that cites this layer's run is a POST-RELEASE row ADMITTED BY THE ARCHITECT'S ACT, and the gates that precede it are not blocked by it.** `[A1 docs/specs/storeroom-publish-proposal-review.md §5.1 item 5 — the ceiling, restated | ordering claim]`
