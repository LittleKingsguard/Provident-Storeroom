## 2. THE FINDINGS, EACH WITH THE INSTRUMENT THAT CAUGHT IT

### 2.1 THE STATE THREE PASSES CALLED IMPOSSIBLE, AND THE ONE MEASUREMENT THAT REFUTED EACH

**WHAT WAS BELIEVED, THREE TIMES, BY THREE DIFFERENT INSTRUMENTS.** The amendment's discriminating state — a parent where the MODE BITS say writable while the KERNEL denies the create — was declared *"not constructible here"*, and the declaration was load-bearing: **it is what REFUSED the first remedy and what justified calling the second one unfalsifiable.**
**WHAT WAS TRUE.** **The state needs no ACL and no mount and no privilege: it is a parent the process OWNS at mode `0o200` — OWNER-WRITE set, OWNER-EXECUTE CLEARED — where `readonly()` answers WRITABLE while the kernel answers `EACCES`, because adding a directory entry additionally requires SEARCH/EXECUTE on the parent.** **It is constructible at `uid=1000`, on an unprivileged runner, which is what every declared runner is.**
**HOW EACH OF THE THREE FELL, AND EACH FELL TO ONE MEASUREMENT:**
1. **A GATE-1 LEG: *"all five declared runners are privileged, so the `EACCES`/`EROFS` refusal class cannot be produced in this suite"*.** **REFUTED BY MEASURING THE CLAIM'S OWN CITATION:** `release.md §1.2`'s five-row table is a table of five **BUILD TARGETS** — `ubuntu-24.04`, `ubuntu-24.04-arm`, `macos-15-intel`, `macos-15`, `windows-2022` — and **it says nothing whatsoever about privilege**; those are GitHub-hosted standard NON-ROOT images. **Measured at `uid=1000`: a `chmod 0555` directory followed by an exclusive create DOES return `EACCES`** (`docs/decisions.md`'s `⟶ CORRECTED 2026-10-13` clause; `docs/defects.md`'s `DEF-20` correction block).
2. **A TEST WRITER: *"`/tmp` is world-writable, so no parent writable-by-BITS is deniable, and a named-user ACL cannot remove an owner's write bit"*.** **TRUE OF `/tmp` AND TRUE OF ACLs — and FALSE of a parent the process owns at `0o200`, which needs neither** (`docs/defects.md`, the same block, instruments `(2)` and `(3)`).
3. **THE SUPERVISOR, CARRYING BOTH INTO TWO ROLE BRIEFS AS ESTABLISHED.** **The instrument that broke the chain was the state's own construction — and the cost stated plainly in the record: *"the cost was not the error — it was that the error was load-bearing."***
**AND THE NEGATIVE CONTROL THAT SETTLES IT, RUN RATHER THAN ARGUED: the WITHDRAWN predicate was driven against the AMENDED one, and the two readings DISAGREE at `0o200` and AGREE at `0o555`.** **That is the whole of the amendment's falsifiability: at `0o555` the mode bit `readonly()` is ALREADY `true`, so the withdrawn arm already answers unreachable there and old and new answers are indistinguishable — which is why the `0o555`-shaped cells PROVE NOTHING about the amendment, and why the `0o200`-shaped cell is the one that does** (`docs/next-steps.md`'s gate-4 adversarial clause; `docs/defects.md`'s `DEF-2026-10-13-B`; `tests/construction_access_probe.rs`'s own cell `acp_a_mode_writable_parent_that_denies_the_create_refuses_at_construction`; `contract.md §10.4` part 5's falsifier sub-clause).
**THE LESSON: A CONCLUSION CAN BE RIGHT AND ITS EVIDENCE WRONG, AND ONLY MEASURING EACH SEPARATELY TELLS THEM APART.** **The right reason was available the whole time and was not the one given.** **And the pattern is not that reviewers err: it is that A CLAIM NOBODY RAN TRAVELS FURTHER THAN ONE SOMEBODY DID.**

### 2.2 THE DEFECT NO REVIEW PREDICTED, FOUND BY A SET THAT READ ONLY THE DOCUMENTS

**WHAT WAS BELIEVED.** The amendment's eight clauses had been reviewed, adversarially attacked, and reconciled; the remaining risk was in the code.

**AND THE FIRST RUN'S OWN FIGURES, AT THE HARNESS'S CAPTURED TRANSCRIPT: `107 PASS · 4 FAIL`, every `FAIL` inside ONE scenario (`G5-AP-07`)`; POST-FIX: `107 PASS · 0 FAIL`, that scenario `PASS 3 · FAIL 0`** (`target/blind-ap-harness/RUN.txt` and `target/blind-ap-harness/RUN-postfix.txt`, both read at their bytes for this document; `docs/specs/storeroom-native-greens.md §10`'s header and `§11`).
**THE FIX IS ONE LOOKUP SWAPPED AT THE ONE POINT THAT DECIDES WHICH ARM A PATH IS ON: `symlink_metadata` (`lstat`) INSTEAD OF `metadata` (`stat`).** **The arms' frontier becomes what step `4b`'s exclusive create already answers — *"an entry of any kind occupies the NAME"* — so a dangling symlink is an OCCUPIED name, arm (a)'s write-mode open answers `ENOENT` and REFUSES, and the construction answers `FilePathUnreachable` with NO instance and nothing created.** **NO SECOND PREDICATE, NO TRUNCATING PRIMITIVE, NO DEPENDENCY: the crate's `[dependencies]` is still EMPTY and `Cargo.lock` still carries exactly one package.**
**THE LESSON: A SET DERIVED FROM THE DOCUMENTS CAN FIND WHAT A REVIEW OF THE DOCUMENTS CANNOT.** **Four review passes read those clauses; the state is one no clause named, and only ASKING THE CLAUSES FOR A STATE did it appear.**

### 2.3 A VACUUM FOUND INSIDE THE PASS WRITTEN TO REMOVE VACUOUS CHECKS

**WHAT WAS BELIEVED.** The pass that audited the amendment's cells for vacuity had removed them; a cell that still read as green was a cell with teeth.
**WHAT WAS TRUE.** **One of the pass's OWN pinned cells asserted something VACUOUSLY TRUE, because the mode word was read BEFORE the `chmod`.** **The cell read `readonly()` at the parent while the parent was still in its default mode, then changed the mode — so the reading it pinned was never the reading the state produces, and the assertion held for the wrong input.**

### 2.7 THE LINE-ANCHOR DRIFT IS A RATE, NOT A TYPO CLASS

**THE RULE, STATED SO IT IS APPLIED RATHER THAN RE-DISCOVERED: CITE BY `§` NUMBER AND BY ROW NAME.** **This document holds to it throughout and cites no line anchor of an appended file anywhere.** **A drift RATE is managed by a CONVENTION; only a typo is managed by an edit.**

### 2.8 THE NODE ITEM, IN THE ARCHITECT'S OWN TERMS

**`D-GP-NODE-1` carries the instruction; `D-GP-REL-0.1.3` carries the cut instruction; and the row states that the two are SEPARATE RULINGS ON SEPARATE SUBJECTS.**
**THE NOTICE, AND IT IS FROM THE `linux-x64` LEG'S OWN RUN LOG, VERBATIM: *"`Node.js 20 is deprecated. The following actions target Node.js 20 but are being forced to run on Node.js 24: actions/checkout@v4.`"***
**WHAT THE NOTICE ACTUALLY NAMES — AND THIS DISTINCTION IS THE WHOLE FINDING: IT NAMES THE **ACTION'S OWN RUNTIME**, NOT THE RUNNER'S NODE AND NOT THE PACKAGE'S.** **`actions/checkout@v4` is a JavaScript action bundled against the `node20` runtime; the HOST then forces it to run on `node24` and warns.**
**SO THE FIX IS THE ACTION'S MAJOR: `actions/checkout@v4` → `actions/checkout@v7`, BOTH OCCURRENCES, and the file's own comment states the shared premise — *"`@v5`'s and `@v7`'s shared premise is the `node24` runtime, so the two pins are the same declaration read at the newest tag that carries it."***
**AND THREE THINGS WERE **NOT** THE PROBLEM, STATED SO THE REMEDY IS NOT MIS-REPEATED:**
1. **THE RUNNER WAS ALREADY NODE 24 AND WAS NOT THE OFFENDER.** **Nothing about the runner's Node moved, because nothing about it was wrong.**
2. **`actions/setup-node@v6` WITH `node-version: '24'` WAS ALREADY CORRECT AND IS UNMOVED.** **Both occurrences still read `@v6` with `node-version: '24'`.** **That step exists for a DECLARED reason the file states at its own site: trusted publishing needs `npm >= 11.5.1`, and the failure it was landed for was `ENEEDAUTH` while the tarball assembled correctly — the CLIENT was too old.**
3. **★ THE `engines` FLOOR IS A DIFFERENT DECLARATION AND IT DOES NOT MOVE.**
**THE FLOOR, AS IT IS RATHER THAN AS IT MIGHT BE: `bindings/js/package.json`'s `engines` field READS `{ "node": ">=18.0.0" }`, and all five platform manifests read the same.** **It is a DECLARED PARAMETER with a PINNED DOMAIN — `parameter-semantics.md §2.6`'s `PAR-PUB-6` declares its domain as *"exactly `{ "node": ">=18.0.0" }`"* — and a HIGHER FLOOR (`>=20`) is a PRICED AND REFUSED alternative at `docs/specs/storeroom-js/contract.md`'s `DD-38`, on the ground that it *"would exclude consumers the carrier itself serves"*.**
**AND THE FLOOR IS HONEST RATHER THAN MERELY PINNED, WHICH IS WHY RAISING IT WOULD BE A FALSE RESTRICTION AND NOT A CORRECTION: the facade's HIGHEST-referenced Node-API class is `6` (`napi_get_value_bigint_int64`, beside `napi_get_all_property_names`) — `Node 12.17.0` / `10.20.0` — and `index.mjs` uses only `node:` builtins and `Object.hasOwn` (`Node 16.9`).** **So the artefact LOADS on runtimes the floor does not exclude and would be excluded from if the floor rose.** **AND THE THING THAT LOOKS LIKE A FLOOR AND IS NOT ONE: `bindings/js/build.rs`'s `NODE_PIN` is `24.11.0`, and it says at its own site that it is THE WINDOWS IMPORT LIBRARY'S FIXED BYTE — *"the import library's version need not equal any consumer runtime's: it need only EXPORT the `napi_*` symbols."***
**AND THE TWO DECLARATIONS MUST NOT BE READ AS ONE ANOTHER, which is a rule that already had a home before this release: `release.md §1.1` item `3` draws exactly this distinction — *"THE FLOOR IS NOT THE PACKAGE'S `engines` FLOOR: `{ "node": ">=18.0.0" }` declares WHAT THE ARTEFACT LOADS ON and this clause declares WHAT THE RELEASE PUBLISHES WITH — two different readers, two different declarations, and neither is the other's."*** **The release PUBLISHES WITH the workflow's Node `24`; the ARTEFACT LOADS ON the manifest's `engines` floor; a guide that reads one as the other tells a consumer they need Node 24 when they do not, or that a Node 18 runtime is unsupported when it is supported.**
**THE LESSON: A DEPRECATION NOTICE NAMES WHAT DEPRECATED, AND THE INSTRUMENT IS READING THE NOTICE'S SUBJECT.** **Three successive readings of this one notice produced three different subjects — the runner, the package's floor, and the action's runtime — and only the third is what the notice says.**
