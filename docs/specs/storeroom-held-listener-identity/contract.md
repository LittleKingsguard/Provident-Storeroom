### §2.1 `HL-1` — THE IDENTITY IS A CALLER-SPELLED STRING, AND ITS DOMAIN IS THE STORE'S

1. **THE TYPE.** **A handle IS a `string`.** **The caller spells it, holds it and passes it back; nothing mints it.** **No counter, no UUID, no scalar and no skip loop exists** (`P: docs/pending.md · P-6`, the ruling on minting, verbatim: *"You don't need to mint anything. The handle is already a unique identifier."*; read with the ruling *"Refuse handles that aren't strings."*). **The set of values in the domain is `{ s : s ∈ String, s ≠ "" }` — a NON-EMPTY string — and every other value is outside it.** `[CONTRACT]`
2. **WHERE THE IDENTITY LIVES, AND THE TWO FABRICATIONS IT RETIRES.** **THE IDENTITY LIVES IN THE STORE, NOT IN A JS CACHE** (`P: docs/pending.md · (AA-2)`, verbatim: *"Move the identity into the store"*). **What this retires, named at its own bytes: `state.tokens` (`bindings/js/index.mjs:1984`) and its read at `:2503`; `Object.freeze({})` at `:1757`; `wrapHandles` (`:1746-1780`); and `encodeHandle` (`:1483-1488`).** **A JS cache is therefore LOAD-BEARING FOR NOTHING, and a cache miss is no longer indistinguishable from a removal, because the identity's presence IS a store row's presence** (`P: docs/pending.md · (AA-2)`, item (ii)). `[CONTRACT]`
3. **UNIQUENESS IS STRUCTURAL AND IT IS THE STORE'S.** **The store holds AT MOST ONE LIVE ENTRY PER HANDLE STRING.** **The guarantee is the PURGE-AND-REPLACE rule's and not allocation's: a reused handle REPLACES, so two live entries cannot share one** (`P: docs/pending.md · P-6`'s rule 2, as read at its own closing clause; `§HL-3`). **The CALLER-SPELLED DUPLICATE STATE — `cfg.listeners` *"duplicates KEPT"* (`docs/specs/storeroom-js/surface.md:161`), the `DD-39` adoption rule and `surface.md:798-812`'s two duplicate cases — DOES NOT SURVIVE IN THAT FORM: a handle names ONE listener, standing at the addresses ONE `listen` gave it** (`P: docs/pending.md · P-6`'s rule 3). `[CONTRACT]`
4. **THE DOMAIN TESTS ARE DIRECT MAP KEY CHECKS, AND `encodeHandle` IS DELETED RATHER THAN REWRITTEN.** **`unlisten` and `register` do `map.has(handle)` / `map.get(handle)` on the one function map keyed by the handle string** (`P: docs/pending.md · P-6`, the ruling that settles fork (g), verbatim: *"This is also irrelevant because tokens is being eliminated and the function lookup is now a direct map key check."*). **The three variants and their two dispositions SURVIVE AS CONSEQUENCES and not as a classifier: a NON-STRING is REFUSED by the class test at both verbs; a STRING that is not in the map is `unlisten`'s NO-OP SUCCESS and `register`'s REFUSAL.** **A BLANK STRING stays the store's own refused form** (`bindings/js/src/crossing.rs:506-512`; the `ListenerHandle` row's first outside value, `docs/specs/storeroom-native/parameter-semantics.md §2.13`). `[CONTRACT]`

### §2.2 `HL-2` — `listen(handle, addresses)`: TWO POSITIONS, THE SECOND A SET

1. **THE SIGNATURE AND THE ARITY FIGURE.** **`listen(handle, addresses)` — arity `2`, position `1` a `string` in `HL-1`'s domain, position `2` a SET of addresses.** **The arity figure moves `1 → 2` at FOUR declared sites, each needing its own dated clause: `docs/specs/storeroom-js/surface.md:1056` (the verb table), `:1071` (*"SOUND: 1, one position"*), `:1590` (the migration table) and `:1605` (the signature sketch); plus `bindings/js/index.d.ts:616` and `bindings/js/index.mjs:2016`, and `PAR-JS`'s row for the verb in `parameter-semantics.md`** (`P: docs/pending.md · P-6`, the ruling *"`listen` gains a handle position"* and its own consequence list; the same ruling's `(A)` clause). `[CONTRACT]`
   **⟶ REPOINTED 2026-10-18 (`RCA-8(g)`, clean-up pass): this item's `index.d.ts:497` — the OLD arity-1 `listen(address)` — is repointed to `index.d.ts:616`, where `listen(handle: Handle, addresses: readonly Address[]): void` now stands; the `index.d.ts` correction of that date moved the bytes.** **The six-site list and the arity figure `1 → 2` are unmoved.**
2. **THE SECOND POSITION'S DOMAIN IS A SET, AND THE SET-POSITION CLASS TEST IS A NEW DECLARED FORM.** **`addresses` is an ARRAY of addresses, each in the store's own address domain; THE EMPTY ARRAY is IN the domain; a SINGLE address supplied as a bare array-of-segments is NOT — the position is a set and a segment list is a different shape** (`P: docs/pending.md · P-7`, the ruling *"Make listeners/constraints accept multiple addresses on creation"*, verbatim; read with its own consequence (ii): *"A SET-POSITION CLASS TEST IS A NEW DECLARED FORM — an `Address` vs `Address[]` discriminator, with its own outside-value set at `§2.5` item 5, and `PAR-JS-5`'s address row gains a set arm"*). **The outside-value set of the set position is: ABSENT · `null` · `undefined` · a non-array · an array carrying a member outside the store's address domain · an array carrying a nested array-of-arrays that is not itself an address.** **The declared answer for every one of them is the surface's ONE thrown form with the store's own code** — `AddressMalformed`, carried verbatim with the generator's own message. `[CONTRACT]`
3. **THE SET IS AN ASSIGNMENT, NOT A UNION.** **`listen(h, S2)` after `listen(h, S1)` DESTROYS `S1` WHOLLY AND INSTALLS `S2`.** **A caller cannot narrow a live handle's standing by omitting an address it previously named; the handle's standing is ALWAYS the last act's set, never cumulative** (`P: docs/pending.md · P-6`'s ruling `(R1)`, verbatim: *"S1 gets purged wholesale, yes"*). **AND `listen(h, S1)` then `listen(h, S1)` IS IDEMPOTENT ONLY IN EFFECT — purge then reinstall the same set — and never by a fast path** (`P: docs/pending.md · (R1)`, its own closing sentence). `[CONTRACT]`
4. **THE ORDER: PURGE, THEN INSTALL, AND NO INTERMEDIATE STATE IS OBSERVABLE.** **The purge of every entry the handle names runs BEFORE the install of the new set, so no observable instant holds both** (`P: docs/pending.md · (M-1)`, verbatim: *"AND IT PRECEDES THE INSTALL SO NO INTERMEDIATE STATE IS OBSERVABLE"*; `P: docs/pending.md · P-6`'s rule 2 (b)). **The store-side operation is a `Home` method BESIDE `mint`/`withdraw`/`adopt`** — **its NAME, its ANSWER (a removed-count or `()`) and its position are three naming questions the ruling leaves to this directory, and this contract DECLARES them as `DECLARED-DEFAULT`:** the name is **`purge`**; the answer is **the count of entries removed, `usize`** (so a drive can assert the wholesale reach numerically, and so the operation is NEITHER `withdraw`'s `bool` NOR `adopt`'s `()`); the position is beside them at `src/store.rs:363-490`. **`alt` priced: an answer of `()`** — priced: it makes the wholesale reach unobservable to the store's own suite and forces every drive to assert it through a later `triggered` read, which is a second-order observable for a first-order fact. `[DECLARED-DEFAULT]`
5. **THE THREE STATES AND THE ONE TRANSITION OF THE ENTRY.** **(a) `listen(handle, addresses)` WRITES THE ENTRY WITH `off` SET** — the reservation; **(b) `register(handle, listener)` CLEARS `off` AND INSTALLS THE FUNCTION**; **(c) `removeListener(handle)` REMOVES THE ENTRY WHOLE, and it is the ONLY route that removes one** (`P: docs/pending.md · P-5`, the ruling ***"Add an explicit delete."*** read with *"handle-with-no-function is not a valid state. Unlisten reserves its token by keeping it in the map with a property declaring it is off."* and the ruling *"Check on/off at the time of decision whether to add the function to the recipients list, not at runtime."*). **SO AN ENTRY WITH NO FUNCTION IS NOT A LAWFUL VALUE, and the state `listen`'s own return once created — a handle the caller holds with no function yet — is modelled as an entry that EXISTS AND IS OFF, which is exactly what ruling (a) provides** (`P: docs/pending.md · P-5`, the ruling on the entry's shape). `[CONTRACT]`
6. **THE BOUND ON THE MAP'S SIZE, AND ITS AUTHORISING CLAUSE.** **The map's size is bounded by the set of handles the caller has LISTENED TO AND NOT EXPLICITLY DELETED** — no longer by a mint, and no longer unbounded by construction, because `removeListener` removes the entry whole (`P: docs/pending.md · P-5`, its own bound clause; `A3`'s `A3` finding — the leak is transformed, not dissolved). **The authorising clause is `A117` (D6)'s *"released with the instance and by nothing else"* read WITH `§2.7` item 1's delete: the growth is compatible with the letter of the retention rule and bounded by the ONE route that removes an entry** (`A: docs/decisions.md · A117` (D6)). `[CONTRACT]`
7. **`listen` GAINS NO CONFLICT TEST AT ALL, AND ITS PURGE REACH IS UNCONDITIONAL.** **`listen` does not test whether the entry it destroys belongs to another actor, and no clause exempts a kernel-held entry** (`P: docs/pending.md · (C-1)`, verbatim: *"`listen` PURGES AND SUCCEEDS, and THE CONFLICT FIRES IN ONE DIRECTION ONLY — AT `addConstraint` AT AN ADDRESS A LISTENER IS ALREADY REGISTERED AT"*; `P: docs/pending.md · (C-2)` item (iv), verbatim: *"`listen` gains NO conflict test at all, and its purge reach stays unconditional"*). **THE DECLARED CONSEQUENCE OF THAT REACH, PRINTED BECAUSE IT FOLLOWS FROM *"EVERYTHING"* AND IS THE RULING'S OWN OUTCOME: the store's home entry is PER ADDRESS and the kernel's `noopListener` registration is SHARED by every pair at that address, so A WRITE TO ONE PAIR AT AN ADDRESS SILENCES DELIVERY FOR EVERY PAIR THERE** (`P: docs/pending.md · (Y-1)`, its declared consequence; `docs/specs/storeroom-constraints/kernel-surface.md §2.2` item 4 — *"`n` pairs at one address are `n` registry rows over ONE store entry"*). **The pair STILL EVALUATES, because `evaluate` reads the registry and not the store** (`§2.8` item 5). `[CONTRACT]`
