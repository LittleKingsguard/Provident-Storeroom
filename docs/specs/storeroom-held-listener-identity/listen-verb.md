## §2. The two positions, item by item

### §2.1 Position `1` — `handle`

**The subject.** **`handle`** — the identity the caller spells (`identity-and-domain.md §1`). **Its `unit`** is unitless — an identity and not a quantity. **Its `domain`** is `{ s : s ∈ String ∧ s ≠ "" }`. **Its `referent`** is the store's own listener entry, and the package's map key. **Its `evaluator`** is **caller-side for the class test and store-side for the admission**, because the class test is the package's and the entry's existence is the store's. **Its `observable`** is the class refusal at an outside value and the entry's presence at an admitted one. **Its clause** is `contract.md §2.2` item 1 and `parameter-semantics.md §2.1` (`PAR-HL-1`). `[CONTRACT]`

### §2.2 Position `2` — `addresses`: THE SET, AND THE SET-POSITION CLASS TEST IS A NEW DECLARED FORM

1. **THE DOMAIN.** **`addresses` is an ARRAY whose every member is an address in the store's own domain — a JS/JSON array of segments, each a `string` key or a non-negative integer index, the empty array included** (`docs/specs/storeroom-native/store-model.md §1.5` item 1, cited and not copied; `docs/specs/storeroom-js/parameter-semantics.md §2.5`'s `PAR-JS-5` address row, gaining a SET arm). **THE EMPTY ARRAY IS IN THE DOMAIN and is the ordinary "listen at no address" act** — **the same reading `cfg.listeners`' empty array carries** (`docs/specs/storeroom-native/parameter-semantics.md §2.12`'s `domain` cell, which declares *"THE EMPTY ARRAY IS IN THE DOMAIN and is the ordinary no-listener store"*). `[CONTRACT]`
2. **THE OUTSIDE-VALUE SET, ENUMERATED — the six classes, and the one shape a caller most often reaches for by mistake.** **OUTSIDE: (i) ABSENT · (ii) `null` · (iii) `undefined` · (iv) a non-array (`number`, `string`, `boolean`, `object`, a function) · (v) an ARRAY WHOSE MEMBER IS OUTSIDE THE STORE'S ADDRESS DOMAIN (a `null` segment, an `undefined` segment, a float index, a negative index, a nested array where a segment belongs) · (vi) AN ARRAY OF ARRAYS THAT IS NOT ITSELF A SET — and the last is the shape a caller reaches for when it spells one address.** **A SINGLE ADDRESS SUPPLIED AS A BARE SEGMENT LIST IS OUTSIDE THE DOMAIN: the position is a set and a segment list is a different shape** (`P: docs/pending.md · P-7`'s set ruling, consequence (ii), verbatim: *"A SET-POSITION CLASS TEST IS A NEW DECLARED FORM — an `Address` vs `Address[]` discriminator, with its own outside-value set at `§2.5` item 5"*). `[CONTRACT]`
3. **THE DECLARED ANSWER FOR EVERY ONE OF THE SIX.** **The surface's ONE thrown form — `{status, message, log}` — with `status` the STORE'S `AddressMalformed`, the message the store's generator's own text, and `log: []`** (`docs/specs/storeroom-js/surface.md §2.5` item 5's one form; `contract.md §2.1` item 6's form rule; `bindings/js/index.mjs`'s `boundaryReject`). **NO STORE ACT IS REACHED ON ANY OF THE SIX, so a refused `listen` changes nothing: no entry, no mirror row, no purge.** `[CONTRACT]`
4. **AND THE ONE THING THE CLASS TEST MUST NOT DO, PRINTED BECAUSE A NAIVE TEST DOES IT.** **The test must distinguish a SET from an ADDRESS WITHOUT INSPECTING SEGMENTS TO DECIDE WHICH IT IS: an array whose first member is an array is a SET; an array whose members are segments is an ADDRESS and is therefore outside this position's domain.** **The discriminator is the MEMBER'S CLASS, read once per member, and never a length heuristic and never a coercion** (`P: docs/pending.md · P-7`'s set ruling, consequence (ii); `docs/specs/storeroom-js/surface.md §2.5` item 5's class-first rule). `[CONTRACT]`
5. **THE SET'S EQUALITY AND ITS CANONICAL KEY — A DECLARED DEFAULT, CARRIED HERE BECAUSE THE SET POSITION FORCES IT.** **Two address sets are EQUAL exactly when they contain the same addresses — SET EQUALITY, not sequence equality — and the canonical key used by `carriesConstraintAt` and by `kernel.pairs`' key shape is the SORTED, INJECTIVELY-SPELLED member list** (`contract.md §2.6` item 6's `HL-DD-3`). **`alt`, priced: DECLARE A CANONICAL ORDER** — priced: it mints an order guarantee `DD-37`/`DD-22` do not carry, and makes a registration's position observable, which no ruling names. **Reversal point: a fresh ruling recorded as an ACTIVE `docs/decisions.md` row, followed by a bounded amendment.** `[DECLARED-DEFAULT]`

## §3. The two orderings: purge-then-install at `listen`, and check-purge-add at a constraint site

1. **AT `listen`: PURGE, THEN INSTALL, AND NO INTERMEDIATE STATE IS OBSERVABLE.** **`listen(h, S2)` DESTROYS EVERY ENTRY `h` NAMED — AT EVERY ADDRESS IT STOOD AT — AND THEN INSTALLS `S2`** (`P: docs/pending.md · P-6`'s rule 2 (a)–(b); `P: docs/pending.md · (R1)`, verbatim: *"`listen(h, S2)` AFTER `listen(h, S1)` IS SET-ASSIGNMENT, NOT UNION — `S1` IS PURGED WHOLESALE"*; `P: docs/pending.md · (M-1)`, verbatim: *"AND IT PRECEDES THE INSTALL SO NO INTERMEDIATE STATE IS OBSERVABLE"*). **THE FOUR STRUCTURES THE ORDER SPANS: the store's `members` buckets (`src/store.rs:341`), the store's `handles` index (`:344`), the package's `state.home` mirror, and the package's `registry` map.** **After the act, all four name the new set and none names the old.** `[CONTRACT]`
2. **AND WHAT THE OPERATION IS *NOT*, STATED SO NO READER CONFUSES THREE DIFFERENT ACTS.** **The purge is NEITHER `withdraw` (`src/store.rs:442-472`, ONE entry by `DD-42` clause (2)'s first-match rule) NOR `adopt` (`:363-384`, which appends)** (`P: docs/pending.md · (M-1)`, verbatim). **It is a FOURTH `Home` method, and the ruling states the three naming questions it leaves: the operation's NAME, its POSITION as a `Home` method beside `mint`/`withdraw`/`adopt` (`src/store.rs:363-490`), and its ANSWER (a removed-count or `()`)** (`P: docs/pending.md · (M-1)`, verbatim: *"WHAT THE PROPOSAL STILL OWES IS SHAPE, NOT SEMANTICS"*). **THIS CONTRACT DECLARES ALL THREE, AS A `DECLARED-DEFAULT` AT `contract.md §2.2` ITEM 4: the name `purge`, the position beside the other three, and the answer the removed count as `usize`.** **`alt`, priced: an answer of `()`** — priced: the wholesale reach becomes unobservable to the store's own suite, forcing every drive to assert a first-order fact through a second-order read. **Reversal point: a bounded amendment.** `[DECLARED-DEFAULT]`
3. **AT A CONSTRAINT SITE: CHECK, THEN PURGE, THEN ADD — AND THE ORDER IS NOT `listen`'S.** **A constraint written to a held pair VALIDATES FIRST, PURGES SECOND and ADDS THIRD, at every site reaching `K-1` from a held pair: `addConstraint`'s overwrite arm, `constraintOn`, `constraintOff`, and the construction's `cfg.constraints` batch** (`contract.md §2.3` item 2; `P: docs/pending.md · (O-4)`, verbatim: *"THAT THE ORDER IS CHECK → PURGE → ADD at every site that reaches `K-1` from a held pair"*). **SO THE TWO ORDERINGS DIFFER AND BOTH ARE DECLARED: `listen` purges first because the caller's own act is the creation and its validation is the class test, which precedes both; a constraint site validates FIRST because a purge with no add is the failure the order exists to prevent** (`P: docs/pending.md · (O-4)`, its own ground). `[CONTRACT]`

## §5. `listen`'s purge reach is unconditional, and what that costs

1. **THE RULE.** **`listen` DOES NOT TEST WHETHER THE ENTRY IT DESTROYS BELONGS TO ANOTHER ACTOR, and no clause exempts a kernel-held entry** (`P: docs/pending.md · (C-1)`, verbatim: *"F-3's four declared assertions survive; … a **no exception for a handle the caller did not mint**"*; `(F-3)`'s own words: *"because the purge ruling is total and applies to every `listen`, with no exception for a handle the caller did not mint"*). **AND F-3 IS THE STATE'S PRODUCER: an app that calls `listen` at an address the kernel holds a pair at PURGES the store's home entry there, and the kernel does not observe it and is not expected to** (`P: docs/pending.md · P-5`'s `(F-3)`, verbatim). `[CONTRACT]`
2. **THE THREE DECLARED CONSEQUENCES, EACH WITH ITS OBSERVABLE — and each is a DECLARED OUTCOME and not a defect.** **(i) THE KERNEL'S `noopListener` REGISTRATION DIES WITH THE PURGED ENTRY, so the address fires nothing for that pair AFTER the purge until the pair is removed and re-added (the `removeConstraint`-then-`addConstraint` route). (ii) THE PAIR STILL EVALUATES — `evaluate` reads the registry, not the store — so a purged pair remains ENFORCED while its delivery resolves to nothing silently. (iii) THE STATE IS DECLARED, so a drive may assert it: `listen(h, [A])` over a kernel-held address, then a write at `A` that violates the pair, asserts the REFUSAL (enforced) and asserts NO INVOCATION (silent)** (`P: docs/pending.md · P-5`'s `(F-3)`, items (i)–(iv), verbatim). `[CONTRACT]`
3. **AND THE ONE THING THE RULING LEFT UNANSWERED, RECORDED RATHER THAN INVENTED.** **`F-3 (iii)` recorded that a purged pair's refusal carries NO TELL; and `F-3 (ii)` recorded that `constraints()` reads `state.constraints` and not the store, so a purged pair appears IDENTICALLY to a healthy one** (`P: docs/pending.md · P-5`'s `(F-3)`, items (ii)–(iii), verbatim). **THE ONE THING STILL OWED FROM THAT FAMILY: *"THE PROPOSAL MUST NAME THE OBSERVABLE THAT SEPARATES THEM, OR WITHDRAW THE ASSERTABILITY CLAIM"*** (`P: docs/pending.md · P-5`'s `(F-3)`, item (ii)'s closing obligation). **THIS CONTRACT WITHDRAWS THE ASSERTABILITY CLAIM FOR THE PAIR'S STORE-STANDING AND KEEPS IT FOR ITS ENFORCEMENT: what a drive asserts is (a) the write is REFUSED — the pair is enforced — and (b) NO BODY IS INVOKED — the delivery is silent; and NO drive asserts a readable difference between purged-but-enforcing and intact, because `"no invocation"` is indistinguishable from `"invoked a no-op"`, the standing `noopListener` entry making `triggered` carry its handle and `deliver` invoke a function that does nothing by construction** (`P: docs/pending.md · P-5`'s `(F-3)`, item (ii), verbatim). **`[NEGATIVE]`**
4. **AND THE CONSEQUENCE AT THE ADDRESS'S OTHER PAIRS, WHICH IS THE RULING'S OWN OUTCOME AND NOT A FINDING.** **The store's home entry is PER ADDRESS and the kernel's `noopListener` registration is SHARED by every pair at that address, so A WRITE TO ONE PAIR AT AN ADDRESS SILENCES DELIVERY FOR EVERY PAIR THERE — a DECLARED CONSEQUENCE and not a defect** (`P: docs/pending.md · (Y-1)`, its declared consequence; `docs/specs/storeroom-constraints/kernel-surface.md §2.2` item 4 — *"`n` pairs at one address are `n` registry rows over ONE store entry"*). **A drive asserts it at two pairs, one address: the write is refused by the constraint that still evaluates, and NEITHER pair's body runs.** `[CONTRACT]`
