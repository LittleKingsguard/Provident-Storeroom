## §1. The identity: one value, one spelling, and where its authority sits

1. **THE HANDLE IS A `string`.** **The caller spells it, holds it and passes it back; nothing mints it.** **The value the store reports in `triggered`, the value the entry's map keys on, the value `unlisten` accepts, the value `register` accepts and the value `removeListener` accepts ARE ONE VALUE AND NOT FIVE SPELLINGS OF ONE** (`contract.md §2.1` item 1; `P: docs/pending.md · P-6`, the rulings *"You don't need to mint anything. The handle is already a unique identifier."* and *"Refuse handles that aren't strings."*). **The direct consequence, stated because a gate-1 finder measured it: `encodeHandle` (`bindings/js/index.mjs:1483-1488`) IS DELETED, NOT REWRITTEN, and `unlisten`/`register` do a DIRECT MAP KEY CHECK** (`P: docs/pending.md · P-6`, the ruling that settles fork (g), verbatim: *"This is also irrelevant because tokens is being eliminated and the function lookup is now a direct map key check."*). `[CONTRACT]`
2. **THE TWO FABRICATIONS THIS RETIRES, EACH NAMED AT ITS BYTES SO NO READER LOOKS FOR THEM LATER.**
   **(i) `Object.freeze({})` AT `bindings/js/index.mjs:1757`.** **It was the JS-side stand-in for a Rust-side identity, and with the handle being a value the caller spells there is nothing to stand in for** (`P: docs/pending.md · P-6`, verbatim: *"AND THE `{}` AT `index.mjs:1757` GOES WITH IT"*). **AND THE "UNIQUE BY ALLOCATION" READING IS RETIRED WITH IT — it was the supervisor's, not the architect's** (`P: docs/pending.md · P-6`, the clause that supersedes that reading).
   **(ii) `state.tokens` (`bindings/js/index.mjs:1984`) AND ITS READ AT `:2503`.** **With the handle being the string the caller supplies, a map from an object to a token has nothing to contain** (`P: docs/pending.md · P-6`, item (4) of the type ruling; `P: docs/pending.md · P-5`'s ruling (2), verbatim: *"nothing in the entry, the crossing or the store holds a token"*). **AND THE READ AT `:2503` IS THE ONE `role_validity` FOUND THE FILING HAD UNDER-PRICED: it was the ONLY source of the home mirror's `token` column for a freshly minted handle** (`P: docs/pending.md · P-5`, gate-1 finding (1), verbatim). **Under this part the mirror's column is the CALLER'S OWN HANDLE, so the read has no subject and the column has a source that is not a map lookup.**
   **(iii) `wrapHandles` (`bindings/js/index.mjs:1746-1780`).** **No subject; DELETED, not rewritten** (`P: docs/pending.md · P-5`'s ruling (1), verbatim). **What it did reduces to *"the handles the store named"*, which the store already has as its own values** (`P: docs/pending.md · P-6`, the token-removal clause). `[CONTRACT]`
3. **WHERE THE IDENTITY LIVES — NOT IN A JS CACHE.** **THE IDENTITY LIVES IN THE STORE** (`P: docs/pending.md · (AA-2)`, verbatim: *"Move the identity into the store"*). **And this is stated for the LISTENER identity and the CONSTRAINT identity alike, because the ruling reaches both: a listener's handle is a store-side row's own key, and a constraint's identity is a store-side fact returned with the pair** (`contract.md §2.6`; `constraint-identity.md §2.6`). **SO A JS CACHE IS LOAD-BEARING FOR NOTHING, and the single point of silent failure `critique` named — *"a cache miss is indistinguishable from a removal"* — has no subject, because the identity's presence IS a store row's presence** (`P: docs/pending.md · (AA-2)`, item (ii)). `[CONTRACT]`
4. **THE UNIQUENESS RULE, AND WHAT IT IS NOT.** **The store holds AT MOST ONE LIVE ENTRY PER HANDLE STRING, and the guarantee is STRUCTURAL AND NOT POLICED: a reused handle REPLACES, so two live entries cannot share one** (`contract.md §2.2` item 3; `P: docs/pending.md · P-6`'s rule 2 as read at its closing clause). **NO TEST REFUSES A DUPLICATE, and none may be added: a refusal would need a code the closed `16`-member set does not carry, and the collision ruling's own disposition of a reused handle is the purge** (`P: docs/pending.md · P-6`, the mint's uniqueness clause: *"a collision is a REPLACEMENT by the purge ruling, and there is nothing to collide with anyway"*; `docs/specs/storeroom-native/contract.md §0.2 · DD-42`'s priced alternatives, whose *"REFUSING the colliding token at `listen`"* is refused there). `[CONTRACT]`

## §3. What a deleted handle is, and is not

1. **A DELETED ENTRY IS NOT A RESERVED ONE.** **`removeListener` removes the entry whole, so the handle is OUTSIDE the domain at `unlisten` and `register` alike, and its store-side entry (if any) is unreachable from the package** (`P: docs/pending.md · P-5`, the explicit-delete ruling, verbatim: *"A DELETED ENTRY IS NOT A RESERVED ONE — `encodeHandle`'s domain test (now `map.has(handle)`) answers FALSE for a deleted handle"*). **This is THE ONE PLACE WHERE *"delete"* AND *"off"* DIFFER OBSERVABLY, and the contract states it in the operator's own terms.** `[CONTRACT]`
2. **THE TWO OBSERVABLES THAT SEPARATE THEM, EACH ASSERTABLE.**
   **(i) AFTER `unlisten(h)`:** the entry EXISTS with `off` set; `register(h, fn)` SUCCEEDS and re-arms it; a later `listen(h, S)` purges and installs as any `listen` would.
   **(ii) AFTER `removeListener(h)`:** the entry is GONE; `register(h, fn)` is REFUSED (`contract.md §2.1` item 5's fabricated row); a later `listen(h, S)` creates a FRESH entry with `off` set — an entry that is a different entry in every structural sense and an equal handle in the value's own sense.
   **A drive asserts each pair and never a mixture** (`contract.md §2.7` items 2 and 10; `removal-members.md §2.7`). `[CONTRACT]`
3. **THE LEAK IS TRANSFORMED AND NOT DISSOLVED — AND ITS BOUND IS DECLARED.** **`A3`, the item's own must-fix: with no delete on `unlisten` and no mint to bound the population, the map's size would be bounded only by the distinct handles the CALLER names.** **The explicit delete is the answer: the map's size is the set of handles the caller has listened to and NOT explicitly deleted** (`P: docs/pending.md · P-5`, the explicit-delete ruling, verbatim: *"the map's size is the set of handles the caller has listened to and not explicitly deleted"*; `contract.md §2.2` item 6). **Its authorising retention rule is `A117` (D6)'s *"released with the instance and by nothing else"*, which makes the growth compatible with the letter of the rule and bounded by the one route that removes an entry** (`R: docs/decisions.md · A117` (D6)). `[CONTRACT]`

## §4. The `off` flag: one read, one instant, and no delivery semantics beyond it

1. **THE FLAG'S WHOLE ROLE.** **`off` is PURELY A RESERVATION MECHANISM: it keeps the handle→entry mapping alive for `unlisten` and `register`, and it has NO DELIVERY SEMANTICS AT ALL BEYOND THE ONE SNAPSHOT-TIME READ — which is why the flag may not be consulted a second time anywhere** (`P: docs/pending.md · P-5`, the A2 ruling, verbatim: *"Check on/off at the time of decision whether to add the function to the recipients list, not at runtime."*; and its item (iii), verbatim). `[CONTRACT]`
2. **THE INSTANT.** **`off` IS READ EXACTLY ONCE, INSIDE THE RECIPIENT-BUILDING LOOP, BESIDE `registry.get(handle)` — `bindings/js/index.mjs:2364`'s site — and the recipients list carries the FUNCTION, never the record; an entry that is absent or `off` is skipped THERE, and the invocation loop (`:2366-2375`) performs `listener(decodeSegments(address))` unconditionally, with no further check** (`P: docs/pending.md · P-5`, the A2 ruling, verbatim). `[CONTRACT]`
3. **WHAT THE TIMING PRESERVES, IN THE CLAUSE'S OWN TERMS.** **(i) `C-2` IS PRESERVED EXACTLY — the decision is frozen when the window opens, so a body that turns an entry `off` mid-window cannot silence a later element; (ii) IT MATCHES THE ALREADY-DECLARED CLAUSE — `docs/specs/storeroom-js/surface.md:1921`'s *"`off` DOES NOT CANCEL A DELIVERY IN FLIGHT"* and `:1920`'s *"`deregister` … is `state.registry.delete(handle)` and nothing else … there is no `finally` and none may be added"*; (iii) IT COLLAPSES TWO QUESTIONS INTO ONE — under a runtime check *"is it off?"* and *"is it still in the map?"* are different questions, and under this timing the recipients list IS the complete answer** (`P: docs/pending.md · P-5`, the A2 ruling, its items (i)–(iii), verbatim). `[CONTRACT]`
4. **AND THE ONE THING THE FLAG NO LONGER HAS TO CARRY: THE PER-ADDRESS TRUTH.** **`unlisten` sets `off` only when the identity no longer stands anywhere, exactly as the survivor re-scan decides today** (`P: docs/pending.md · P-5`, the A4 ruling, verbatim: *"`unlisten` sets `off` only when the identity no longer stands anywhere, exactly as `:2571`'s survivor re-scan decides today. The flag is per-handle AND per-standing, which is what the home mirror already computes."*). **`A4` IS CLOSED BY THAT RULING, and this part carries the arm as a state the flag must be able to express and not as an open question** (`P: docs/pending.md · P-5`, the same clause). **AND `A4`'S SURVIVAL AT `cfg.listeners` IS STATED WITH IT: the purge retires the duplicate at `listen` but NOT at `cfg.listeners` adoption, so the one-address-duplicate arm survives in part** (`P: docs/pending.md · P-5`, gate-1 finding (4), verbatim). `[CONTRACT]`
5. **THE MAP'S SHAPE, SINCE THE FLAG LIVES ON ITS VALUE.** **ONE MAP, KEYED BY THE HANDLE STRING, whose value carries the function together with the entry's own listening state: `Map<handle, { fn, off }>`.** **The `token` property the earlier filing's value record carried is GONE, because the token is** (`P: docs/pending.md · P-6`, fork (d), verbatim: *"the map becomes `Map<handle, {fn, off}>`, keyed by the identity the addon also holds"*). **AND THE MAP'S NAME: this contract declares it `registry` — the name the shipped entry already uses at `bindings/js/index.mjs:1984` — so no rename is minted and no second structure is declared.** `[CONTRACT]`

## §5. The identity's scope: the store's, not the session's

1. **THE SCOPE IS THE STORE INSTANCE'S, AND IT IS ONE RULE: at most one live entry per handle string, per instance.** **`PAR-13`'s *"unique per instance and per session"* spelling is RETIRED WITH THE MINT** (`docs/specs/storeroom-native/parameter-semantics.md §2.13`; `contract.md §0.4`'s dated uniqueness clause, cited and not re-derived). **The uniqueness this change rests on is STRUCTURAL (`§1` item 4) and does not need a scope clause at all.** `[CONTRACT]`
2. **NO PERSISTENCE, AND NO CLAUSE OWED.** **`P: docs/pending.md · (AA-3)`'s three facts, quoted: the `file` tier persists STORE STATE and handles are not part of it; a handle from a prior session names nothing after a restart, `cfg.listeners` re-supplies the boot's own handles; and `PAR-13`/`A67`'s uniqueness ground need not be replaced, because the session scope is a property of what is saved and not of a rule.** **The ruling's own conclusion: *"NO CLAUSE IS OWED"*** (`P: docs/pending.md · (AA-3)`, verbatim). **This part states THE FACT and writes no session rule, exactly as the ruling directs.** `[NEGATIVE]`
3. **AND THE ONE PLACE THE FACT IS OWED AS A LANDING: the store's persistence section, so no reader derives a session rule the model does not have** (`contract.md §8` item 11). `[REQUIREMENT]`
