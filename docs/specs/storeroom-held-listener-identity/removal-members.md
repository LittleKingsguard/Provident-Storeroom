## §2. `removeListener(handle) -> undefined`

1. **THE SIGNATURE.** **`a.removeListener(handle) -> undefined`.** **The receiver is the store; position `1` is `handle`, a non-empty `string` in `identity-and-domain.md §2`'s domain; the arity is `1`; the return is `undefined`.** `[CONTRACT]`
2. **THE SUCCESS RETURN IS THE NORMAL RETURN, AND THE FAIL IS THE THROW — NOT A RETURNED DISCRIMINANT.** **`P: docs/pending.md · P-5`'s `(R3)`, verbatim: *"SUCCESS IS THE NORMAL RETURN (`undefined` for `removeListener`, the documented value for `removeConstraint`) AND THE FAIL IS THE THROW — the discriminant is the throw's presence, and the verbose message is the store's generated `message` carried verbatim"*.** **AND `§2.5`'s *"a rejection is NEVER a SECOND FORM … no returned union"* STANDS, `PAR-JS-17`'s `alt` cell keeps its refusal, `DD-12`'s thrown form is unmoved, and `index.d.ts`'s `StoreRefusal` needs no companion success type** (`P: docs/pending.md · P-5`'s `(R3)`, verbatim; `docs/specs/storeroom-js/surface.md:1228-1233`). `[CONTRACT]`
3. **WHAT IT DOES, IN THE OPERATOR'S OWN TERMS — THE TWO ACTS, BOTH DECLARED.** **(i) It REMOVES THE MAP ENTRY WHOLE** (`listen-verb.md §4`, state `3`). **(ii) It WITHDRAWS THE STORE'S HOME ENTRIES THE HANDLE NAMED — all of them, at every address, by the purge's own total reach** (`contract.md §2.2` item 4; `HL-DD-2`). **NO `unlisten` IS ISSUED AND NO SEPARATE WITHDRAWAL VERB IS REACHED: the removal IS the purge, and the map entry's deletion follows it** (`contract.md §2.7` item 7's order). `[CONTRACT]`
4. **AND THE CONSEQUENCE THE RULING REQUIRES STATED, BECAUSE IT IS THE ONE PLACE *"DELETE"* AND *"OFF"* DIFFER OBSERVABLY.** **A DELETED ENTRY IS NOT A RESERVED ONE: a deleted handle is OUTSIDE the domain at `unlisten` and `register` alike, and its store-side entry (if any) is unreachable from the package** (`P: docs/pending.md · P-5`, the explicit-delete ruling, verbatim; `identity-and-domain.md §3`). `[CONTRACT]`
5. **AND THE INTERACTION THE RULING NAMES, AT ITS OWN SITE.** **A deleted handle is outside `map.has`, so `register` on it is REFUSED — `critique`'s warning that this *"resurrects the pre-ruling A1 defect through the new door"* is answerable only by the DECLARED REFUSAL** (`P: docs/pending.md · P-5`, the interaction clause, verbatim). **THE REFUSAL IS `identity-and-domain.md §2` ITEM 3'S FABRICATED ROW, and WHAT THE CALLER IS TOLD is `OWED`** (`contract.md §10` item 5). `[OWED]`

## §3. `removeConstraint(pair) -> undefined`

1. **THE SIGNATURE.** **`a.removeConstraint(pair) -> undefined`.** **Position `1` is `pair`, a `{address, id}` record in the constraint methods' own pair domain: `address` an address SET per `constraint-identity.md §4` item 3 and, at the removal act, THE PAIR'S OWN SET; `id` a non-empty `string`. The arity is `1`; the return is `undefined`.** `[CONTRACT]`
2. **WHAT IT REMOVES, IN THE RULING'S OWN WORDS.** ***"`removeConstraint` REMOVES EVERYTHING — THE PAIR, ALL N ADDRESS ROWS, THE KERNEL'S REGISTRATION, AND THE STORE-SIDE HOME ENTRY"*** (`P: docs/pending.md · P-5`'s `(R4)`, verbatim). **AFTER IT THE PAIR IS GONE FROM `constraints()`, GONE FROM THE KERNEL'S `pairs` AND EVERY ADDRESS ROW, AND ITS STORE-SIDE HOME ENTRY WITHDRAWN — so the address no longer fires the `noopListener` and no longer appears in `watched` as standing for that pair** (`P: docs/pending.md · P-5`'s `(R4)`, verbatim). `[CONTRACT]`
3. **IT IS A THIRD AND STRONGER OPERATION, AND NEITHER OF THE TWO IT IS OFTEN MISTAKEN FOR.** **It is neither `constraintOff` (a TOGGLE re-registering a parked stub and keeping the pair carried, `bindings/js/index.mjs:3082`/`:3118`) nor the kernel's `withdrawRegistration` (`bindings/js/src/constraint-kernel.mjs:460-476`, whose comment at `:472-474` says it leaves the store's home entry STANDING)** (`P: docs/pending.md · P-5`'s `(R4)`, verbatim). **AND THE OBSERVABLE DISTINCTION THE RULING SUPPLIES: `constraints()`'s return SHRINKS by one element per `removeConstraint`, where `constraintOff` leaves it standing — so the two become observably distinguishable through the read model** (`P: docs/pending.md · P-5`'s `(R4)`, verbatim: *"which is the distinction `critique` asked for and this ruling supplies"*). `[CONTRACT]`
4. **AND THE ONE THING IT DELETES THAT NOTHING ELSE DOES: THE PAIR'S IDENTITY** (`constraint-identity.md §3`; `P: docs/pending.md · (AA-2)`, closing sentence). `[CONTRACT]`

## §4. The order of the four removals, and the one rule it carries

1. **THE RULING'S OBLIGATION, VERBATIM: *"THE PROPOSAL MUST STATE THE ORDER OF THE FOUR REMOVALS AND THAT NO INTERMEDIATE STATE IS OBSERVABLE"*** (`P: docs/pending.md · P-5`'s `(R4)`, verbatim; `(M-2)`, verbatim: *"THE ORDER OF THE FOUR REMOVALS IS R4'S OWN OUTSTANDING OBLIGATION"*). **THE FOUR STRUCTURES IT NAMES: the kernel row, its N address rows, the entry's read model and the store's home entry.** `[CONTRACT]`
2. **THE ORDER THIS CONTRACT DECLARES (`HL-DD-4`), ONE LINE:** **(1) VALIDATE the pair and the call's class; (2) WITHDRAW the store's home entries the pair's addresses hold, through `K-6`'s route; (3) DELETE the KERNEL's `pairs` row and its N address rows; (4) DELETE the JS ENTRY — `state.constraints`'s value, its identity included; (5) RETURN `undefined`.** `[DECLARED-DEFAULT]`
3. **WHY THAT ORDER AND NOT ANOTHER, STATED SO THE CHOICE IS CHECKABLE.** **The alternative — JS ENTRY FIRST — is priced and refused: a failure in the store withdrawal would leave the store holding entries the package no longer names, which is precisely the orphan class `(M-2)` and `(X-6)` exist to abolish** (`P: docs/pending.md · (M-2)`, verbatim: *"a listener the app never heard of, that no app verb can remove, that holds an address the app still thinks it owns"*; `P: docs/pending.md · (X-6)`, verbatim: *"(vi) THE ORPHAN DOES NOT RETURN — `(D-vi)` IS RETIRED INSTEAD, AND THAT IS A SAVING"*). **Reversal point: a bounded amendment.** `[DECLARED-DEFAULT]`
4. **AND THE OBSERVABLE THE ORDER'S ATOMICITY RESOLVES TO: after ANY thrown arm all four structures stand as they stood; after the success return all four are gone.** **NO INTERMEDIATE STATE IS OBSERVABLE, and the observable is the ABSENCE of one: a drive reads the four structures only at the act's two ends, because no declared member exposes the middle** (`P: docs/pending.md · P-5`'s `(R4)`; `contract.md §2.7` item 7). `[CONTRACT]`
5. **AND THE ONE STEP THE ORDER'S STEP `(2)` DEPENDS ON, NAMED: `K-6`'s route is `removeConstraint → K-6 → removeListener → purge`, and it has no cycle because `removeListener` reaches no constraint member** (`remove-member.md §2.9` item 6; `contract.md §2.9` item 6). `[CONTRACT]`
6. **AND THE ONE THING THE ORDER DOES NOT SETTLE, RECORDED AS THE `OWED` IT IS.** **`kernel.handles` keeps the PRE-PURGE handle after an app `listen` purges a pair's store entry (per `(D-vi)`), so the removal's `removeListener`-equivalent may name a handle the store no longer holds — and WHETHER THE REMOVAL IS A NO-OP ON THAT STATE OR WHETHER THE PURGE IS ALSO REACHED FROM THE REMOVAL is `OWED`** (`P: docs/pending.md · (M-2)`, its closing paragraph, verbatim; `contract.md §2.9` item 7 and `§10` item 4). `[OWED]`

3. **AND THE ONE RULE THAT MAKES `R-B4` REACHABLE AT ALL, PRINTED BECAUSE IT WAS THE ITEM'S DECISIVE BLOCKER.** **`X5`'s fail arms had NO STATUS: the closed sixteen-member set names no code for *"a well-formed in-domain handle that this instance does not hold"*, `AddressMalformed`'s trigger is *"a present argument OUTSIDE its domain"* and this value is INSIDE it, and `DD-40` bars minting a status.
