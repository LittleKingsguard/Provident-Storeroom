## §2 · THE CRASH, ITS ROOT CAUSE, AND THE FIX

### §2.1 The throwing cell, named

**`bindings/js/greens/greens.mjs` cell `JSG-08.1`, at its drive, `greens.mjs:731` as filed:**

```js
const h1 = i8.listen(['ev']);      // ← a BARE call: no `thrown()`, so the refusal killed the process
```

Its sibling sites in the same file are bare too (`:752`, `:775`–`776`, `:783`–`785`, `:807`, `:1358`–`1360`,
`:1392`, `:1398`), as are `live-drive.mjs:211`/`:229`/`:850`/`:1243`/`:1251` and
`file-tier-save/scenarios.mjs:891`/`:1015`.

### §2.2 The root cause, stated at the code

**`listen` MOVED: `listen(address)` with the package minting an opaque handle is SUPERSEDED by
`listen(handle, addresses)` with the CALLER spelling the handle and the call answering `undefined`.**

- **The declaration** — `bindings/js/index.d.ts:616`: `listen(handle: Handle, addresses: readonly Address[]):
  void;`, with `Handle = string` (`index.d.ts:309`) and position `2` **a SET of addresses**.
- **The refusal, measured** — `storeCreate({journalLength, listeners: []})` then `listen(['ev'])` throws
  `{status:'AddressMalformed', message:"'ev' is not a legal address segment in '', … listen's first argument is
  an Array, and a listener's handle is a non-empty string this caller spells", log: []}` — **byte-identical to
  the object `npm run greens` died on.**
- **Why it was FATAL rather than a red cell** — every other stale drive in these files sits inside the file's
  own `thrown()` helper and therefore reports a `FAIL`; `JSG-08.1`'s drive did not, and `listen`'s refusal is a
  thrown plain object, so Node terminated the process before the report, before `process.exit`, and before
  either of the leg's other two runners.

### §2.3 The fix — a re-derivation, and why it is not a swallow

**No `try`/`catch` was added around any throw. No cell was retired. No expectation was re-spelled to fit a
measurement.** What was changed is the DRIVE, at the sites that threw or that the throw reached:

1. **The handle is SPELLED by the drive and the address is passed as the ONE-MEMBER SET** the declaration
   takes: `listen(H1, [['ev']])`, `register(H1, fn)`, `unlisten(H1)`.
2. **`triggered`'s element is the PAIR `{handle, address}`** in the code as it stands, so every cell whose
   subject is *the identity the registration was given* now reads the pair by its `handle` member —
   `carriesHandle(set, handle)`, exactly the re-derivation
   `bindings/js/test/constraint-kernel-deliverymodel.test.mjs:127`–`150` carries for this same change on
   2026-10-18. **The project already has one convention for this; this pass followed it rather than inventing
   a second.**
3. **Cells whose subject is the MINTED opaque handle are LEFT RED, and each carries the type precondition its
   own words already presupposed** (`typeof h === 'object' && h !== null && …`). Without that guard, three of
   them would report **FALSE GREENS** on the code's current answer — `JSG-08.3`'s *"spells no token"* is
   vacuously true of `undefined`, `JSG-08.18`'s *"the SAME opaque value"* is vacuously true of
   `undefined === undefined`, and `JSG-08.20`'s *"a FRESH handle"* is trivially true of two spellings. **A
   guard that turns a vacuous green into an honest red is the opposite of a swallow, and it is recorded here
   so it is not read as a weakening.**
4. **`JSG-01.17` and `JSG-09`'s drive were re-pointed to the caller's handle and go GREEN**, because their
   subject (a withdrawal answering `undefined`; `register`'s domain and refusal form) is untouched by the
   signature and is true of the code.

**THE LAYER LABEL IS UNTOUCHED AND WAS VERIFIED.** `const LAYER`, `const APP_LAYER`, the head comment and the
print in `greens.mjs` are byte-identical, so `bindings/js/test/register.test.mjs`'s `S-LAYER` cell still reads
what it read (`register.test.mjs` is 2/2 green after this pass, and in the same run as everything else).

### §2.5 ★ WHAT THE CRASH FIX DID **NOT** BUY, AND WHY IT CANNOT BE BOUGHT FROM HERE

**`npm run greens` STILL EXITS `1` AT ITS FIRST RUNNER, SO THE SCRIPT'S SECOND AND THIRD RUNNERS ARE NOT
REACHED BY THE SCRIPT.** The reason is structural and not the crash:

- the script is `node greens.mjs && node live-drive.mjs && node file-tier-save/scenarios.mjs` (root
  `package.json`);
- `greens.mjs` ends `process.exit(fail > 0 ? 1 : 0)`, and after the fix it reports **48 honest `FAIL`s**;
- so `&&` short-circuits, and **no fix to the crash can make the chain reach runner 2 while 48 cells are
  correctly red.**

**Reaching the chain requires one of exactly two things, neither of which this pass may do:** **execute the
classified REWRITEs** so the runner reports `0` `FAIL` (`D-20` defers that to the next pass), or **change the
script's chaining** (the root manifest is outside this pass's write scope). **Both runners were therefore
measured by direct invocation** — the measurement the crash had hidden is in §2.4 — and the question is put to
the architect in §7.

**THE ROOT CAUSE AS A STATEMENT FOR THE RECORD:** *the greens leg's crash was not a defect in the entry and not
damage from the archival; it was `listen`'s 2026-10-18 signature change reaching a battery that had never been
re-derived against it, in a drive that was not wrapped in the file's own throw-catcher. Two stale subjects
(`JSG-01.9`'s twelve-member figure and the `listen` signature) account for the first 40 `FAIL`s, and the same
signature accounts for the two runners and one scenario that never ran.*
